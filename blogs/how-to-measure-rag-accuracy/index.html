How to Measure RAG Accuracy

Comprehensive framework for RAG accuracy measurement. Retrieval metrics, generation metrics, and end-to-end evaluation methods.

Retrieval Quality Metrics

Measuring what the retriever finds

  • •Recall@K measures whether relevant documents appear in top K retrieved chunks, critical because missed documents cannot inform generation. RAG systems need high recall at context window size; if maximum retrievable chunks is 10, recall@10 determines ceiling for answer quality. Teams must measure recall at multiple K values, because recall@5 may be low but recall@10 high, acceptable when context window accommodates more chunks. Tracking recall by query type reveals systematic retrieval failures; low recall for specific categories indicates embedding or chunking problems requiring targeted fixes rather than global changes that may not address root cause of category-specific retrieval gaps where relevant documents semantically distant from queries despite conceptual relevance due to vocabulary mismatch or embedding space geometry.
  • •Precision@K measures fraction of retrieved chunks relevant to query, affecting generation because irrelevant context dilutes attention from useful information. Low precision forces generator to filter noise, increasing hallucination risk when model attends to wrong chunks. Teams must balance recall and precision, because maximizing both proves impossible; retrieving more chunks (higher recall) typically reduces precision by including marginal documents. Optimal trade-off depends on generator robustness to irrelevant context, where strong models tolerate lower precision while weak models require higher precision to avoid distraction. Precision measurement requires relevance judgments for each retrieved chunk, not just query-document pairs, because partial relevance (chunk contains some useful information) grading better captures retrieval quality than binary relevant/not relevant for tasks where information redundancy means multiple chunks contain overlapping useful content, making precision harder to define than recall given fuzzy relevance boundaries.
  • •Mean Reciprocal Rank measures position of first relevant chunk, crucial because generators attend most strongly to early positions. Low MRR means relevant documents appear late in results, reducing their influence on generation even when present. Teams should optimize ranking before increasing K, because improving position of relevant chunks benefits generation without enlarging context window. MRR improvement often easier than recall improvement for hard queries, requiring better embedding similarity or re-ranking models rather than retrieving additional candidates, making MRR primary metric for ranking quality where recall already adequate but generation still fails due to position bias that pushes relevant chunks beyond generator's attention horizon.

    Generation Quality Metrics

    Measuring what the LLM produces

    • •Faithfulness measures whether generated claims have support in retrieved chunks, detecting hallucination where model invents information. Low faithfulness indicates generation ignores retrieval, possibly due to position bias, instruction following failure, or model lacking capability to extract required information. Faithfulness correlates with answer correctness but provides more actionable signal because unfaithful responses may accidentally be correct (hallucinating correct information) or incorrect (hallucinating wrong information), requiring separate measurement because correct but unfaithful answers mislead about model behavior where response accidentally matches ground truth despite ignoring sources, giving false confidence in generation reliability that faithlessness metrics reveal by checking alignment with provided context regardless of outcome correctness.
    • •Answer relevance measures whether response addresses user question, independent of factual correctness. Low relevance indicates misunderstanding or off-topic generation, often from poor instructions or retrieval providing irrelevant context that misdirects model. Relevance should be measured before correctness because irrelevant answers fail regardless of factual accuracy; optimizing relevance first prevents wasting effort on correct answers to wrong questions. Relevance assessment requires judging whether response answers intended question, which demands understanding user intent more than factual verification, often requiring human evaluation or LLM-as-judge with carefully designed prompts that check question-answer alignment rather than factual accuracy, because relevance errors differ fundamentally from factual errors and require different remediation strategies where prompt improvements or query understanding fixes address relevance while retrieval or grounding fixes address faithfulness.

      End-to-End Accuracy

      Combined retrieval and generation measurement

      • •Correctness measures whether final answer matches ground truth, integrating retrieval and generation quality. Low correctness may stem from retrieval failure (missing information), generation failure (ignoring retrieved information), or model knowledge gaps (information not in retrieval but model could answer from training). Diagnosing root cause requires decomposing correctness into faithfulness and retrieval recall, because aggregated score alone cannot guide improvement toward addressing specific failure mode where retrieval improvement benefits some failures while generation improvement benefits others, requiring both metrics to allocate optimization effort effectively.
      • •Answerable rate measures fraction of queries where system provides any answer versus refusing due to low confidence. Trade-off exists between answerable rate and correctness; answering more queries typically reduces average correctness because system attempts harder questions where uncertainty higher. Teams must calibrate refusal threshold balancing coverage against accuracy, where mission-critical applications prioritize high correctness on answered queries while sacrificing answerable rate, while user-facing applications prioritize answering most queries even if some answers incorrect, because different use cases tolerate different error-cost trade-offs where medical advice requires high precision (refuse when uncertain) while entertainment search prefers high recall (answer always, accept occasional errors).

        Building Test Sets

        Ground truth for meaningful measurement

        • •Golden dataset requires queries, relevant document IDs, and ground truth answers. Building this set is expensive but essential for reliable measurement because evaluation without ground truth cannot determine correctness. Teams should invest in test set creation before optimizing RAG systems, because measurement enables improvement while lack of measurement leads to random changes and false progress. Test set size needs to detect meaningful differences; typically 500-1000 examples provide sufficient power for most metrics given typical effect sizes, because smaller test sets have wide confidence intervals making improvement detection impossible while larger sets than needed provide diminishing returns for statistical power given fixed time and annotation budget.

          Automated Evaluation

          Scaling measurement with LLM-as-judge

          • •LLM-as-judge can approximate human evaluation for some metrics at fraction of cost, but requires validation against human judgments. Teams should calibrate judge on test set, measuring correlation before trusting automation. Judge models have biases toward certain response styles; validation catches these biases before they distort optimization. Automated metrics enable continuous evaluation, essential for rapid iteration where human evaluation becomes bottleneck. However, automated metrics should complement rather than replace human evaluation, using humans for validation holdout and drift detection while relying on automation for development iteration, because LLM judges may miss subtle errors that humans catch, making fully automated evaluation without human oversight risky for quality-critical applications.
