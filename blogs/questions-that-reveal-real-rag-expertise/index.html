Retrieval Architecture Questions

Testing deep understanding beyond vector search basics

  • •Explain how you would diagnose and fix a RAG system that retrieves semantically similar but factually incorrect documents for certain query types. Expert answer discusses analyzing failure patterns (vocabulary mismatch, semantic similarity failure, chunk boundary issues), implementing hybrid search with keyword weighting, query rewriting, or re-ranking as solutions depending on root cause. Junior answer suggests increasing chunk count or changing embedding model without diagnostic framework. This question separates those who systematically debug retrieval from those who guess changes randomly, because fixing retrieval requires identifying whether problem stems from query representation, document representation, or similarity function before selecting appropriate remediation strategy from toolkit of techniques (query expansion, hybrid search, multi-vector retrieval, re-ranking) that address different failure modes where embedding similarity fails for vocabulary mismatch but keyword search succeeds, making hybrid approach appropriate only for specific failure patterns rather than universal improvement.
  • •How would you design chunking strategy for a document collection containing mixed content types: technical specifications with tables, narrative policies, and code examples? Expert discusses semantic boundary detection, content-type specific strategies (table preservation, code block integrity), overlap percentages, and evaluation of chunking impact on retrieval. Junior suggests fixed token size regardless of content type, missing that optimal chunking varies by content because tables require preserving column relationships, code needs function-level boundaries, and policies benefit from section-based chunks. This question tests understanding that chunking is content-dependent design decision requiring empirical validation rather than universal parameter, because retrieval quality depends on alignment between chunk granularity and typical query information needs where fine-grained chunks work for fact lookup but coarse chunks needed for contextual understanding, requiring different strategies for different content types within same collection.

    Generation and Grounding Questions

    Testing instruction following and hallucination prevention

    • •Your RAG model ignores retrieved context and answers from training data when context conflicts with model knowledge. How do you fix this? Expert discusses system prompt engineering emphasizing context priority, few-shot examples showing conflict resolution, temperature adjustment, and fallback to context-only fine-tuning if prompting insufficient. Junior may only suggest prompt changes without systematic approach, missing that fundamental conflict between parametric knowledge and provided context requires instruction design that explicitly teaches model to defer to context when contradictions arise, because models trained to maximize training likelihood naturally prefer parametric knowledge when uncertain, requiring prompt examples demonstrating context-override behavior and potentially fine-tuning on synthetic examples where model must choose provided information over conflicting internal knowledge to learn appropriate behavior for RAG use cases where retrieved documents always supersede parametric memory regardless of model confidence in training data.
    • •How do you evaluate whether a RAG answer is faithful to retrieved chunks versus hallucinated? Expert discusses automated faithfulness metrics (contextual recall, answer faithfulness), LLM-as-judge with specific rubrics, human evaluation sampling, and citation requirements. Junior may only mention human review, missing that manual evaluation doesn't scale for continuous monitoring. This question tests understanding that faithfulness requires separate measurement from correctness because correct answers may be unfaithful (hallucinating correct information) while incorrect answers may be faithful (following bad context), requiring distinct evaluation methodologies that check claim-level source attribution rather than answer-level correctness where faithfulness errors require generation fixes (better prompting, fine-tuning) while correctness errors from bad retrieval require retrieval fixes (better chunking, search), making metric separation essential for root cause diagnosis.

      Evaluation Methodology Questions

      Testing measurement and experimental rigor

      • •How do you determine whether a RAG system change improves quality or the difference is due to random variation? Expert discusses statistical significance testing, confidence intervals, A/A tests for baseline stability, and effect size measurement. Junior may not have framework for determining improvement significance, potentially shipping regressions or missing genuine improvements due to underpowered evaluation. This question separates those who approach evaluation scientifically from those who make decisions based on single point estimate differences without uncertainty quantification, because RAG system evaluation requires understanding variance to avoid chasing noise where random fluctuation exceeds meaningful improvement threshold, necessitating statistical methods that account for multiple comparisons when testing many changes, because without rigor, teams waste cycles optimizing for random variation that doesn't represent real quality change, making evaluation noise primary cost driver for iteration speed where inability to trust measurement forces manual validation that limits experiment velocity.

        Debugging and Optimization Questions

        Testing systematic problem-solving approach

        • •Walk through your process for debugging a RAG system that produces wrong answers for specific query categories. Expert discusses analyzing examples to determine failure type (retrieval vs generation vs both), examining retrieved chunks for relevance, checking chunk quality (boundary placement, information completeness), testing generation with known good context to isolate component, and iterating based on findings. Junior may lack systematic decomposition, trying random fixes without isolating root cause. This question tests debugging methodology because effective RAG optimization requires distinguishing between retrieval failures (wrong documents retrieved) and generation failures (right documents ignored), requiring different remediation strategies where retrieval problems need chunking, embedding, or search improvements while generation problems need prompt engineering, fine-tuning, or model selection, making root cause diagnosis prerequisite for effective action where treating all failures identically wastes effort on changes that cannot address actual problem type.

          Production Operations Questions

          Testing operational readiness beyond prototype

          • •How do you monitor RAG system quality in production without ground truth labels for every query? Expert discusses sampling for human evaluation, automated metrics as proxies (faithfulness, retrieval confidence), drift detection for query distribution and document collection changes, and alerting thresholds calibrated to business impact. Junior may not have monitoring strategy, learning about degradation only from user complaints. This question separates prototype builders from production engineers because production RAG requires continuous quality measurement without online labels, using techniques like embedding drift monitoring (detecting query distribution shifts), confidence scoring (retrieval similarity distribution changes), and automated faithfulness estimation (LLM-as-judge on sampled traffic) to detect degradation before user complaints, enabling proactive remediation rather than reactive firefighting where quality erosion continues unnoticed until significant user impact triggers investigation that could have occurred weeks earlier with proper monitoring in place.
